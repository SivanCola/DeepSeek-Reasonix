# OpenCode Go 配置升级（版本 10）

[English](OPENCODE_GO_UPGRADE.md)

本次修复解决 1.38.2 的本地能力误判：OpenCode Go DeepSeek 使用 Anthropic
Messages、`thinking = "enabled"` 和保存的 `max` 时，旧逻辑可能将其识别为二元
开关，在请求发出前拒绝构建执行模型或独立配置的规划模型。

## 自动调整

用户全局配置版本 7、8、9 在一次启动中升级到 10。已知模型按推荐接口分组：
DeepSeek V4 Flash、Pro、Flash Vision Experimental 使用 Chat Completions；其他
模型按固定的 `github.com/sky-valley/pi` v0.84.20 内置目录及已验证补充目录选择。
例如 Qwen3.8 Max 推荐 Chat，MiniMax M3 推荐 Anthropic。未知模型保留原连接，
不根据名称前缀猜测接口。

原连接优先保留原接口模型组，否则保留原默认模型所属组。其他组生成 `go-chat`
等稳定名称，冲突时添加数字后缀。只有凭据引用、传输设置及模型设置相容才复用。
保留模型 ID、定价、输出上限、视觉覆盖和显式禁用项。`low/high/max` 不降档；旧
DeepSeek `enabled` 转为 `high`，Responses 的 `none` 转到 Chat 时使用 `disabled`。
显式自定义声明继续由适配器校验，不兼容时提供具体错误。

识别依据是实际请求地址、API 格式和精确模型 ID，包括完整 `/zen/go/v1/messages`。
自定义域名、查询参数、非标准路径、自定义请求体保持原样，迁移摘要说明原因。
项目文件只做运行时兼容，不写入仓库。迁移只执行一次，之后手动选择受支持的
其他接口会保留。三个 DeepSeek 适配器共享深度能力；Responses 使用 `none` 表示关闭。

## 历史、搜索与恢复

默认、规划、视觉、守护、恢复、子代理及配置档、机器人、搜索引用按用途更新。
旧会话和标签页通过独立记录解析引用，不改写消息、工具结果、思考内容和用量。
目标被删除或身份改变时报 `MIGRATED_MODEL_UNAVAILABLE`，不会替换成其他账户。

新的选择优先使用当前连接和当前默认模型，再考虑旧别名。修改代理、请求头或
凭据环境变量名不会阻止新选择。旧会话仍校验原连接；要使用编辑后的连接，须
显式重新选择模型，即使模型名称未变。重选保留会话内容，并在会话元数据中保存
可选的 `model_identity` 摘要，后续重启校验这次确认的连接。摘要不包含解析后的
API 密钥，复制和分支会保留该字段。旧数据缺少字段时使用原迁移记录；旧版本
写入器若丢弃字段，新版本下次恢复会再次要求确认，不会静默接受已变化的连接。

原来显式启用的 DeepSeek Anthropic/Responses 搜索保留为独立连接，沿用原接口
和凭据引用。显式指派同步更新，自动搜索优先沿用该账户；保存的搜索身份失效时
明确报错。原有 `web_search = false` 保持关闭。

桌面端用选定的同一配置快照构建运行时，创建会话资源前预检本地角色能力。
执行模型使用 `disabled` 时规划模型仍可使用 `max`。真正无效的错误包含角色、
模型、实际力度、来源、接口及支持值，并保留原错误类型。启动失败结束加载状态，
提供设置和重试入口。输入框的 `auto` 显示解析后的默认值。

协议切换复用已有消息转换与缓存身份规则。首次请求可能降低缓存命中率；不会
清空或主动压缩历史，相同历史的后续序列化保持稳定。运行中控制器保留当前配置，
新构建使用新快照。

## 持久化与回退

升级在 `config.toml` 旁创建私有权限文件：

| 文件 | 内容 |
| --- | --- |
| `config.toml.opencode-go-v10.backup` | 原始字节备份；原文件已包含的敏感值也需保护。 |
| `config.toml.opencode-go-v10.json` | 引用映射及凭据引用、传输设置的身份摘要，不含解析后的密钥。 |

配置编辑锁覆盖重读、规划、备份、准备记录和原子替换，保留编码、换行风格、注释和
未知字段，改写结果会先重新解析再替换原文件。若 `config.toml` 是符号链接，两个附属
文件会创建在链接目标旁，链接到 dotfiles 目录时会出现新的未跟踪文件。
映射在匹配的配置提交后才生效，提交标记支持最后确认写入中断后的恢复。后续升级
中断时，上一代已提交记录继续可用；普通保存会在移除未知字段前确认待完成记录。

恢复前关闭 Reasonix，将备份恢复为 `config.toml`，保留对应迁移记录及权限；下次
启动可安全重试。不要将记录放到另一个账户的配置旁。1.38.2 可读取、保存升级后的
TOML；独立记录可跨越旧版保存及版本 9 再升级过程。未来配置版本不会被降级。

下一次正式候选版本必须完成[验收矩阵](OPENCODE_GO_VALIDATION.md)。
